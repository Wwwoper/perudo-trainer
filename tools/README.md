# Эмуляторы

Python-порты логики приложения и скрипт скриншотов. Вместо человека играют и отвечают боты, на выходе — подробные логи и сводка. Нужен только Python 3.10+ (внешних пакетов нет).

| Файл | Что эмулирует | Запуск |
|---|---|---|
| `emulator.py` | партии между ботами: движок, Палифико, Calza, стили и уровни ботов | `python3 tools/emulator.py --games 300 --quiet` |
| `trainer_emulator.py` | «Тренажёр»: ситуации, проверка ставки по правилам, оценка, очередь повторов | `python3 tools/trainer_emulator.py --shows 300` (`--repro` — случай из отчёта) |
| `drill_emulator.py` | «Упражнения»: задачи A и B, ответы «учеников», учёт попыток | `python3 tools/drill_emulator.py --tasks 300` |
| `screenshots.py` | снимки экрана для README (Playwright, воспроизводимые) | `python3 tools/screenshots.py` (`--list`, `--only имя`, `--out папка`) |
| `sound_lab.html` | лаборатория звуков: правка нот, проверка, прослушивание, «Сыграть раунд», копирование рецепта в `src/sound_recipes.js` | открыть `/tools/sound_lab.html` на статическом сервере |
| `emu_cases.py` | случайные входы и ответы эмуляторов для теста `tests/emulators.test.js` | — |

Логи по умолчанию пишутся в `logs/`, `trainer_logs/`, `drill_logs/` (в git не попадают); папку меняет `--out`.

## Не разойдутся ли эмуляторы с приложением

`npm test` запускает `tests/emulators.test.js`: `emu_cases.py` генерирует случайные входы, те же входы идут через `src/`, результаты сравниваются. Проверяются правила (`legal`, `minLegal`), вероятности (`probBid`, `bestBid`), варианты хода (`compareOptions`), правило округления в упражнении, проверка ставки в тренажёре (включая текст сообщения), решения ботов и 20 партий целиком ход в ход.

Если тест упал, значит, логика приложения и эмулятора разошлась. Поправьте эмулятор (или приложение, если ошибка в нём). Без `python3` тест пропускается.

## Ограничения

- В `emulator.py` играют только боты: за столом нет человека, поэтому память ботов о блефе соперника не используется (в приложении она действует только против человека).
- Сама случайность у Python и JavaScript разная. Совпадение «ход в ход» в тесте достигается подачей одного и того же потока чисел в оба кода. В обычных запусках результаты совпадают статистически, а не побитно.
